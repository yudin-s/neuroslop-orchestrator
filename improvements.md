# Improvements / Что не хватает

Ниже — список улучшений к текущему MVP мультиагентного окружения (orchestrator + 4 роли, Ollama, артефакты, патчи, events + UI).

## P0 — устойчивость и контроль качества (сделать в первую очередь)

1) Нормализация и валидация плана **на стороне кода**
- Сейчас порядок в основном держится промптом.
- Нужно: гарантировать pipeline `security_preflight → backend → frontend → qa → security(Q&A)`.
- Дополнительно: выкидывать/игнорировать лишние роли и пустые таски.

2) JSON-retry/repair слой для LLM
- Маленькие модели периодически ломают JSON.
- Нужно: 1–2 ретрая с инструкцией “верни строго валидный JSON без пояснений”, возможно с уменьшением температуры.

3) Patch hygiene + безопасное применение
- Перед apply делать `git apply --check`.
- После apply автоматически выводить `git diff`/краткий summary.
- Ограничить, куда можно писать патчи (allowlist директорий), и блокировать попытки писать в `.env`, ключи, `node_modules`, и т.д.

4) Гейты после apply
- После применения патчей запускать проверки (если доступны): `npm run lint`, `npm test`, `tsc`, `pytest` и т.п.
- При ошибках: останавливать пайплайн и не продолжать автоприменение следующих патчей.

## P1 — работа с контекстом репозитория

5) Repo scanner (read-only “профиль репо”)
- Автоматически собрать:
  - где frontend/backend (папки, `package.json` workspaces)
  - какие команды есть в scripts (`lint`, `test`, `build`)
  - какие тестовые фреймворки (jest/vitest)
  - наличие NestJS модулей, тип Mongo интеграции (mongoose/prisma/native)
- Этот профиль давать оркестратору/ролям как компактный контекст.

6) Политика чтения файлов
- Сейчас есть только `max_read_bytes`.
- Нужно: denylist (`node_modules`, `.git`, `.env*`, секреты) + allowlist ключевых файлов.

## P1 — артефакты под стек React + NestJS + Mongo

7) Машинно-читаемый контракт API
- Помимо `api_contract.md` лучше иметь минимальный `openapi.yaml` или DTO/схемы.
- Это снизит рассинхрон frontend/backend и улучшит тест-план.

8) MongoDB contracts
- Описание коллекций/индексов/уникальностей/миграций/seed.
- Иначе патчи будут часто "работают на словах".

## P2 — наблюдаемость

9) Расширить Event Stream
- Добавить длительности шагов (start/end), ошибки, ретраи, используемые модели.
- (Опционально) грубые метрики размера ответа.

10) Улучшить web UI
- Фильтрация по типам/ролям.
- Кнопка “скачать events.jsonl”.
- Отображение ошибок и ретраев.

## P2 — надёжность LLM вызовов

11) Retry/backoff на Ollama
- Сетевые/серверные ошибки случаются.
- Нужны таймауты по ролям и общий лимит.

12) Стандартизировать “контракт задач”
- Каждая роль должна ссылаться на входные артефакты и выпускать конкретные выходные.
- Иначе оркестратор будет склеивать несопоставимые результаты.

## P2 — тесты

13) Тесты на план
- Модель вернула неправильный порядок → нормализатор исправляет.

14) Тест на apply патча
- Временный `git init` репо, patch apply, проверка что файлы поменялись.

15) Тесты на denylist/allowlist путей
- Попытка написать в запрещённый путь → отказ.
